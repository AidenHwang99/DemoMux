# DemoMux macOS 0.3.5 · 数据目录入口修复验收

2026-11-09 · 构建 11 · Apple 芯片 / macOS 26 · 临时签名试用版

## 问题与原因

实际数据目录及 6 项内容存在。复现旧版「打开数据文件夹」后，Finder 分栏视图停留在路径左端，真正的数据列处于屏幕外。单独改成打开文件夹 URL 后，Finder 仍可能复用该错误滚动位置，因此不将此中间方案记为修复通过。

最终改为调用 Finder 的文件定位接口，优先选中目录内的 Components，促使 Finder 滚动到实际数据列；没有组件时选择已存在的项目记录或其他内容，空目录则直接打开。界面增加可选取路径、复制路径、主要文件说明及失败反馈。

## 已执行

- 读取目录清单确认数据存在，未移动或清空实际目录。
- 最终安装版 0.3.5 / 11 点击按钮后，Finder 显示 Accounts.json、CaddyData、Components、instance.lock、Projects.json、Tailscale，同时显示组件目录内的 Caddy-2.11.9 与 Tailscale-1.104.5。
- 点击「复制路径」后显示成功及 ⇧⌘G 指引。
- 增加路径与说明后，既有原生布局 / 设置回归通过，见 [日志](macos-v0.3.5-layout-regression.log)。最终 Finder 定位分支由实际安装版桌面操作验证。
- 核对 App / helper 签名、版本、资源一致性、源码路径与个人信息排除，以及 ZIP 校验值。

## 范围

本版只修改数据目录入口与说明，不改变数据位置、账号、发布路由或卸载范围。没有新增全套公网回归；此前发布与卸载覆盖见 [0.3.4](macos-v0.3.4.md)。未通过移动真实数据目录制造缺失或权限错误，相关反馈属于已实现的保护分支。
